# Task: Global Walk Lock, Cancellation Cleanup, and Savepoint API Fix

## Problem Statement
The pipeline currently prevents only same-book concurrent walks. A walk on another book can use the same shared SQLite connection, active execution cannot observe cancellation, and onboarding/re-onboarding can replace the current book while work is still writing. Walk modules also issue raw SAVEPOINT statements through the shared connection, bypassing the adapter's transaction-owner guard. This critical fix implements the confirmed override: exactly one active walk globally, cancellation interrupts active execution and purges only output owned by that run after execution stops, onboarding/book switching waits for cancellation and cleanup, and all savepoint activity is adapter-owned. Existing uncommitted changes in `app/pipeline/api_review.py`, `app/pipeline/walks/runner.py`, `app/pipeline/walks/walk_2f_character_description.py`, `app/pipeline/walks/walk_2g_voice_audition.py`, `app/pipeline/walks/walk_2i_delivery.py`, and `tests/pipeline/test_walk_2f.py` must be preserved.

## Dependencies
- Plans O, P, and Q of `epub-audiobook-pipeline-rewrite` (completed; current pipeline-only surface)
- Existing `walk_run` reservation/status schema and `WalkRunner` reserved execution path
- Existing `PipelineStorage.transaction()` owner-thread guard and `HeartbeatStorage`

- A persisted or in-process run cannot overlap any other active walk, regardless of book or entry path.
- Active cancellation is observable at execution checkpoints, reaches a terminal status, purges only demonstrably run-owned generated output after stopping, and leaves manual/other-run/shared data intact.
- Onboarding, re-onboarding, and book switching cannot make replacement state current before cancellation and cleanup finish.
- No pipeline walk or operation uses an unowned raw SAVEPOINT; both adapters enforce ownership and release savepoints on all exception classes.
- Schema migrations are idempotent, existing data remains readable, all focused regression tests pass, and the listed pre-existing working-tree changes remain intact.
